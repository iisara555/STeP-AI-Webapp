# Synthetic lifecycle authority spike — NOT FOR PRODUCTION

Run `python3 -m unittest -v` in this directory. No real process manager, host policy, remote service, or production code is used. FakeManager only writes synthetic event rows to a separate SQLite file.

The first constructor binds a positive integer capacity in the initialized store; subsequent constructors must supply the same value. SQLite FULL synchronous transactions reserve capacity and a random ID before a synthetic start. `start` returns `(operation_id, current_state)` both for new requests and replays; the state is a snapshot at return, not a promise of future state. Idempotency keys are scoped to the **claimed** subject and bound to payload.

A nonblocking, lifetime-held local flock prevents another cooperating Authority using the same lock path from opening and recovering while the first is live. Call `close()` only after all operations have completed and before a deliberate handoff; concurrent close/operation is unsupported. A crashed process releases its lock. A closed instance cannot operate, and recovery is restricted to construction. Startup converts ambiguous nonterminal states to UNKNOWN, retaining capacity; VERIFIED_EMPTY resumes release. Another per-call flock serializes model operations. These are cooperative local locks, not process-manager fencing, and depend on all participants using the same stable path and lock inode. Lock-file deletion/replacement, path aliases, non-cooperating writers, forked descriptors, and filesystem locking semantics are not secured.

State-change triggers record history, checked for allowed transitions and consistency with operation rows on each transaction. For example, a direct RUNNING-to-RELEASED update is fenced before new admission. This catches some inconsistencies only: **arbitrary store modification, coordinated rewriting of records/history/triggers, deletion, replacement, or rollback cannot be reliably detected without an independent trusted anchor**. The capacity and other metadata have the same limitation. SQLite integrity checks do not authenticate state. The checks do not establish security against a writer able to alter the store or lock files. Opening a missing store does not silently recreate it; initialize explicitly creates a new store.

Subject strings are unauthenticated inputs, not principals: any caller can claim another subject. Subject comparisons model matching only and are not access control, identity isolation, or authorization. The tests explicitly demonstrate spoofing.

The fake's synchronous stop-event append is an *assumption* behind VERIFIED_EMPTY, not real process termination evidence. If the synthetic start effect occurs and the manager raises, the operation remains LAUNCHING until restart, then becomes UNKNOWN; capacity stays reserved, and neither retry nor stop resolves it. This is fail-safe within the cooperative fake model but unrecoverable in this prototype. Restart never reconciles UNKNOWN and cannot distinguish no-send from ambiguous send. Process crash tests cover eight transition/effect boundaries, not power loss. This prototype does not verify filesystem durability, simulate fsync errors, protect paths, establish OS principal isolation or scope exclusivity, fence a real manager, prove liveness, or provide cgroup/systemd handoff or termination proof. Never integrate with a real manager or production system.

## Verdict: PARTIAL

The tests exercise a fail-closed synthetic state model and persisted crash boundaries under the stated cooperative, untampered-store assumptions. Real recovery and lifecycle safety remain blocked on independent isolation, fencing, process-handoff, and termination-proof requirements.
