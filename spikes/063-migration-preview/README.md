# Synthetic metadata preview spike — PARTIAL

**SYNTHETIC FIXTURES ONLY. NOT FOR PRODUCTION USE.** This is a disposable, standalone, local pure-function experiment, not an API or migration. It is not lossless or production-ready; never supply real exports, personal data, credentials, or secrets. Source consulted: `supabase/migrations/20261022122700_tenant_workspace.sql`: memories, sessions, documents use tenant/owner/visibility/workspace; auth user IDs refer to `auth.users`; private grants/states contain ciphertext. No credentials, database, network or destination client are used.

Only an artificial metadata projection is accepted: type, id `record-N`, tenant_id `tenant-N`, owner_id `user-N`, visibility and workspace_id. Mapping rows must explicitly contain `user-N` to `sub-N`; duplicate endpoints are ambiguous and malformed rows invalidate all mappings. Missing/extra fields, OAuth credential fields, unsupported types, and shared or unclear visibility fail closed. Documents are blocked regardless of mapping: no public document import was established. Reports contain counts and one reason per input position, never input values. Run `python3 preview.py` and `python3 -m unittest -v`.

`preview()` requires `records` to be a list; any other container raises `TypeError('records must be a list')` without returning misleading counts or echoing its value. Within a list, repeated syntactically valid record IDs are blocked across all owners, tenants and types, including when another occurrence has malformed or extra fields; malformed occurrences may retain their earlier validation reason. Matching is exact and scoped only to the supplied list. This does not check destination, prior-batch, differently formatted or real-world identifier collisions.

`candidate_only` is not a migration authorization, payload validation, a guarantee of importability, or a destination operation. This projection omits all actual content, relationships, tenant authorization, destination collisions, and production schemas beyond the minimal source metadata. It cannot accept raw SQL rows or export formats; field restrictions deliberately reject such rows. No discovery of live mappings, OAuth revocation/reconnection, shared semantics, file contents or direct DB import is implemented. Synthetic identifier syntax cannot establish provenance of arbitrary supplied data; do not use real data. No generic secret detector is claimed: output is value-free, and fields outside the projection are rejected.

The schema-shaped `adapter.adapt()` also accounts for each list position with a value-free disposition. It counts unsupported row keys even for unknown categories and malformed envelopes, counts explicit unknown categories independently, and checks duplicate synthetic UUIDs even on those blocked rows. `ambiguous_ownership_count` counts rows containing at least one ownership/visibility field when the owner is invalid or unmapped, visibility is not private, or workspace is non-null; it is a count of affected rows, not a count of separate problems. Rows without any such fields are blocked but not included in this diagnostic count. These diagnostics may overlap, and missing or malformed rows are still represented in dispositions. Reports never include input keys or values.

Verdict: PARTIAL — deterministic, per-input fail-closed classification can be rehearsed without a destination; migration feasibility and real-world safety are not established.

**Owner decisions applied (see `docs/migration-decisions.md`).** A record with `visibility: workspace` and a valid synthetic workspace ID is reported as `deferred_shared`: it stays in the source until the destination supports sharing, and is neither dropped nor converted to a private copy. Malformed shared rows remain `shared_or_ambiguous_visibility`. `mapping.propose_mappings()` builds an administrator review list by exact, case-insensitive email match (`matched`, `unmatched`, `ambiguous`, `invalid`); every row starts `approved: False`. `approved_mappings()` releases only `matched` rows whose `approved` is literally `True`. The review list contains emails and is for administrators only. Both functions accept synthetic `@example.test` fixtures only and refuse anything else.
