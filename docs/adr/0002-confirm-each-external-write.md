# ADR 0002 · ยืนยันการเขียนข้อมูลภายนอกเป็นรายครั้ง รวมงานตามรอบ

- สถานะ: ยอมรับแล้ว (accepted) 2026-10-24
- ที่มา: ย้ายมาจาก PR #19 ฉบับร่าง ADR อีกฉบับใน PR นั้น (web-only Desktop parity) ไม่ได้นำมา
  เพราะ [ADR 0001](0001-server-engine-direction.md) เปลี่ยนทิศทางไปแล้ว ส่วนกติกานี้ยังใช้ได้กับทิศทางใหม่

วันที่ 24 ตุลาคม 2569 ผู้ใช้เลือกให้ตรวจเนื้อหาและยืนยันก่อนการเขียนข้อมูลภายนอกแต่ละครั้ง
แทนการตั้งการอนุมัติล่วงหน้าสำหรับงานตามรอบ เพื่อให้ผู้ใช้ตรวจข้อมูลและปลายทางจริงของแต่ละการกระทำ
งานตามรอบจึงอ่านข้อมูลและเตรียมร่างตามขอบเขตที่ยินยอมไว้ได้ แต่ต้องรอยืนยันก่อนส่งอีเมล สร้าง Tasks
แก้ไฟล์ หรือกดส่งฟอร์ม; การยืนยันหนึ่งครั้งไม่เป็นสิทธิ์สำหรับรอบถัดไป

การเชื่อมต่อบัญชีและความยินยอมให้ AI อ่านบริบทเป็นคนละเรื่องกับการยืนยันนี้
เนื้อหาหรือปลายทางที่เปลี่ยนหลังยืนยันต้องให้ตรวจใหม่ และต้องตรวจสิทธิ์ของเจ้าของงานก่อนเขียนจริง
การตัดสินใจนี้เป็นกติกาของฟีเจอร์ที่จะพัฒนา ไม่ใช่การสั่งให้ส่งหรือแก้ข้อมูลภายนอกในแชตนี้

## กับ engine บน server (ADR 0001)

ADR 0001 ข้อ 5 เปิด Google แบบ "เขียนเมื่อผู้ใช้อนุมัติทีละครั้ง" ซึ่งตรงกับกติกานี้
tool host ของ server ในระยะ 3 ต้องส่งคำขออนุมัติของ engine ไปให้ผู้ใช้ผ่าน gateway ทุกครั้ง
และต้องไม่จำการอนุมัติข้ามครั้ง (ไม่ใช้ "จำไว้" ของ Desktop กับการเขียนภายนอก)
